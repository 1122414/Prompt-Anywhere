# Prompt Anywhere v0.3 体验打磨升级计划

> 文档日期：2026-05-04  
> 适用项目：Prompt Anywhere  
> 执行对象：OpenCode / 开发 Agent  
> 当前阶段：v0.3 体验打磨版  
> 核心目标：让用户保存 Prompt 更快、搜索 Prompt 更准、调用 Prompt 更顺。

---

## 0. 本阶段总原则

本阶段不是重构产品，不是增加复杂 PromptOps 能力，也不是做在线平台。

本阶段只围绕一个目标：

> 把 Prompt Anywhere 从“功能可用”打磨成“日常顺手”。

用户理想路径应变成：

```text
复制一个好用 Prompt → 一键从剪贴板新建 → 补标题和分类 → 保存
Ctrl + Alt + P 呼出 → 搜索关键词 → Enter 复制 → 窗口自动隐藏 → 粘贴使用
```

---

## 1. 本阶段任务边界

### 1.1 本阶段必须做

本阶段必须完成以下 6 个核心体验功能：

1. 搜索结果高亮
2. 空状态提示
3. 复制成功 Toast
4. 复制后自动隐藏快速窗口
5. 快捷键可视化提示
6. 一键从剪贴板新建 Prompt

同时允许顺带做以下轻量增强：

1. 搜索结果摘要
2. 快捷窗口键盘提示
3. 复制、保存、导入等操作的统一反馈封装
4. 为后续收藏、最近使用、搜索排序预留元数据字段和接口

### 1.2 本阶段严禁做

本阶段严禁开发以下内容：

1. 在线模板市场
2. 账号系统
3. 云同步
4. 团队协作
5. 多模型调用
6. A/B 测试
7. Prompt 评分系统
8. 复杂工作流画布
9. AI 自动优化 Prompt
10. 插件系统
11. 大规模 UI 重构
12. 数据格式破坏性变更
13. 必须联网才能使用的功能
14. 需要数据库迁移的大改动
15. 改变现有核心使用路径的交互重构

### 1.3 本阶段开发原则

1. 保持当前产品功能全部可用。
2. 不破坏现有 Prompt 文件结构。
3. 不强制用户迁移数据。
4. 新功能尽量通过独立组件、工具函数、服务层实现。
5. UI 调整以小步增强为主，不大改页面布局。
6. 所有新增功能必须有失败兜底。
7. 后续可扩展能力要预留接口，但不要提前实现复杂功能。

## 3. 任务一：复制成功 Toast

### 3.1 目标

用户执行复制、保存、导入、恢复等操作后，必须获得明确反馈。

当前用户可能不知道操作是否成功，尤其是复制后没有感知。本任务要解决这个问题。

### 3.2 要做什么

新增一个轻量 Toast 反馈机制。

至少支持：

```text
已复制到剪贴板
Prompt 已保存
Prompt 已更新
已从剪贴板创建 Prompt
导入完成
备份完成
操作失败，请重试
```

### 3.3 触发场景

必须接入以下场景：

1. 复制 Prompt 成功
2. 快速窗口复制成功
3. 新建 Prompt 成功
4. 编辑 Prompt 保存成功
5. 从剪贴板新建 Prompt 成功
6. 导入模板成功
7. 复制失败
8. 保存失败
9. 剪贴板读取失败

### 3.4 推荐实现

建议新增统一通知工具，而不是在每个页面里直接写弹窗逻辑。

推荐接口：

```python
class NotificationService:
    def success(self, message: str, duration_ms: int = 1600):
        pass

    def warning(self, message: str, duration_ms: int = 2200):
        pass

    def error(self, message: str, duration_ms: int = 2600):
        pass
```

如果现有项目已经有类似组件，应复用现有组件。

### 3.5 UI 要求

Toast 应满足：

1. 不阻塞用户操作。
2. 自动消失。
3. 不弹系统模态框。
4. 不遮挡主输入区。
5. 文案短，不超过 20 个中文字符为宜。
6. 快速连续触发时，不应无限堆叠导致界面混乱。

### 3.6 验收标准

1. 点击复制后出现“已复制到剪贴板”。
2. 快速窗口 Enter 复制后出现反馈。
3. 保存 Prompt 后出现“Prompt 已保存”。
4. 复制失败时出现错误提示。
5. Toast 不影响继续搜索和输入。

## 4. 任务二：复制后自动隐藏快速窗口

### 4.1 目标

快速窗口应更像启动器工具。用户搜索到 Prompt 后，按 Enter 复制，窗口自动隐藏。

### 4.2 要做什么

在快速搜索窗口中增加复制后的窗口行为控制。

推荐快捷键行为：

| 操作 | 行为 |
|---|---|
| Enter | 复制选中 Prompt，并自动隐藏窗口 |
| Ctrl + Enter | 复制选中 Prompt，并尝试自动粘贴 |
| Shift + Enter | 复制选中 Prompt，但不隐藏窗口 |
| Esc | 关闭窗口 |
| ↑ / ↓ | 切换搜索结果 |

### 4.3 本阶段边界

本阶段必须实现：

1. Enter 复制并隐藏。
2. Shift + Enter 复制但不隐藏。
3. Esc 关闭窗口。

本阶段可以预留但不强制实现：

1. Ctrl + Enter 自动粘贴。
2. Alt + Enter 打开变量填写。

如果自动粘贴已有实现，则接入；如果没有，不要为了它引入复杂依赖。

### 4.4 推荐配置预留

建议预留配置项：

```json
{
  "quick_window": {
    "hide_after_copy": true,
    "default_enter_action": "copy_and_hide",
    "shift_enter_action": "copy_keep_open",
    "ctrl_enter_action": "copy_and_paste"
  }
}
```

本阶段只需要保证默认配置有效，不要求做完整设置 UI。

### 4.5 异常处理

1. 如果复制失败，不隐藏窗口。
2. 如果没有选中 Prompt，Enter 不执行复制。
3. 如果搜索结果为空，Enter 不报错。

### 4.6 验收标准

1. Ctrl + Alt + P 打开快速窗口。
2. 搜索 Prompt。
3. 按 Enter 后复制成功，并自动隐藏窗口。
4. 按 Shift + Enter 后复制成功，但窗口保持显示。
5. 搜索结果为空时按 Enter 不崩溃。

## 5. 任务三：空状态提示

### 5.1 目标

当页面没有内容时，不要显示空白。用户应明确知道下一步可以做什么。

### 5.2 要做什么

为空状态增加提示组件。

至少覆盖以下状态：

1. 没有任何 Prompt。
2. 当前分类下没有 Prompt。
3. 搜索无结果。
4. 内置模板为空或读取失败。
5. 最近使用为空，如果已有相关模块。
6. 收藏为空，如果已有相关模块。

### 5.3 文案建议

#### 无 Prompt

```text
还没有 Prompt

你可以：
- 新建一个 Prompt
- 从剪贴板保存
- 导入内置模板
- 导入本地 Markdown / TXT 文件
```

按钮建议：

```text
新建 Prompt
从剪贴板新建
导入模板
```

#### 搜索无结果

```text
没有找到匹配的 Prompt

你可以：
- 换个关键词试试
- 清空搜索条件
- 从剪贴板新建一个 Prompt
```

按钮建议：

```text
清空搜索
从剪贴板新建
```

#### 分类为空

```text
当前分类还没有 Prompt

你可以新建一个 Prompt，并保存到这个分类。
```

按钮建议：

```text
新建到当前分类
```

### 5.4 推荐实现

建议封装一个 EmptyState 组件。

推荐参数：

```python
class EmptyState:
    title: str
    description: str
    actions: list
    icon: optional
```

### 5.5 验收标准

1. 新安装且无数据时，主列表显示空状态提示。
2. 搜索无结果时，显示搜索空状态。
3. 点击“从剪贴板新建”可以进入对应流程。
4. 空状态不会破坏当前布局。

## 6. 任务四：一键从剪贴板新建 Prompt

### 6.1 目标

让用户保存好用 Prompt 的流程更短。

用户常见场景：

```text
在网页、聊天记录、文档中看到一段好用 Prompt → 复制 → 打开 Prompt Anywhere → 从剪贴板新建 → 保存
```

### 6.2 要做什么

新增“从剪贴板新建 Prompt”入口。

入口位置建议：

1. 主界面新建按钮旁边。
2. 空状态提示中。
3. 快速窗口中，可选。
4. 菜单栏或工具栏，可选。

### 6.3 流程

```text
点击“从剪贴板新建”
→ 读取剪贴板文本
→ 如果有文本，打开新建 Prompt 表单
→ 将剪贴板文本填入 Prompt 正文
→ 自动生成一个临时标题
→ 用户选择分类/标签
→ 保存
→ Toast：已从剪贴板创建 Prompt
```

### 6.4 标题自动生成规则

建议从剪贴板内容中生成临时标题。

规则：

1. 取第一行非空文本。
2. 去掉 Markdown 标题符号、列表符号和多余空格。
3. 最长 30 个中文字符或 60 个英文字符。
4. 如果第一行太短，使用“未命名 Prompt”。

示例：

```text
请帮我把下面的文章总结成 5 个要点
→ 请帮我把下面的文章总结成 5 个要点
```

```text
# 英文润色助手
→ 英文润色助手
```

### 6.5 剪贴板校验

必须处理以下情况：

1. 剪贴板为空。
2. 剪贴板不是文本。
3. 剪贴板文本过短。
4. 剪贴板文本过长。
5. 剪贴板读取失败。

推荐提示：

```text
剪贴板没有可用文本
```

```text
剪贴板内容过长，请确认后保存
```

### 6.6 数据保存要求

1. 不直接静默保存，必须打开编辑表单让用户确认。
2. 默认分类可以是“未分类”或当前选中分类。
3. 保存后刷新列表。
4. 保存失败不能丢失用户内容。

### 6.7 快捷键预留

建议预留全局快捷键：

```text
Ctrl + Alt + S：从剪贴板新建 Prompt
```

本阶段可以先在配置中预留，不强制完整实现全局快捷键注册。如果实现成本低，可以实现。

### 6.8 推荐接口预留

```python
def create_prompt_from_clipboard(default_category: str | None = None) -> None:
    pass


def build_prompt_draft_from_clipboard_text(text: str) -> PromptDraft:
    pass
```

### 6.9 验收标准

1. 复制一段文本后，点击“从剪贴板新建”。
2. 新建表单自动填入正文。
3. 标题自动生成。
4. 用户保存后，列表出现该 Prompt。
5. 剪贴板为空时，有 Toast 提示，不崩溃。

## 7. 任务五：搜索结果高亮

### 7.1 目标

用户搜索后，应知道为什么某个 Prompt 被匹配到。

### 7.2 要做什么

搜索结果中高亮关键词。

高亮范围：

1. Prompt 标题
2. 分类名
3. 标签
4. 正文摘要

### 7.3 示例

用户搜索：

```text
翻译
```

结果显示：

```text
中英【翻译】助手
标签：英文 / 【翻译】 / 润色
...请将以下内容【翻译】成自然流畅的英文...
```

### 7.4 匹配规则

本阶段只要求关键词高亮，不要求复杂语义高亮。

必须支持：

1. 单关键词高亮。
2. 多关键词高亮。
3. 大小写不敏感。
4. 中文关键词。
5. 特殊字符不导致正则错误。

可以暂不支持：

1. 拼音高亮。
2. 模糊匹配字符级高亮。
3. 语义匹配解释。

### 7.5 推荐实现

建议将高亮逻辑封装成纯函数，方便测试。

```python
def highlight_text(text: str, query: str) -> HighlightedText:
    pass
```

如果 UI 框架支持富文本，应返回可渲染片段，而不是拼接 HTML。

推荐返回结构：

```python
[
  {"text": "中英", "highlight": False},
  {"text": "翻译", "highlight": True},
  {"text": "助手", "highlight": False}
]
```

### 7.6 安全要求

1. 不要直接把用户输入拼进 HTML。
2. 不要让特殊字符破坏渲染。
3. 搜索词为空时不高亮。
4. 高亮失败时展示普通文本。

### 7.7 验收标准

1. 搜索标题关键词时，标题中高亮。
2. 搜索标签关键词时，标签中高亮。
3. 搜索正文关键词时，摘要中高亮。
4. 输入特殊字符不会崩溃。
5. 清空搜索后，高亮消失。

## 8. 任务六：搜索结果摘要

### 8.2 要做什么

摘要规则：

3. 摘要长度建议 60-100 个中文字符。
4. 摘要中关键词要高亮。

### 8.3 示例

```text
文章总结助手
...请将以下文章总结为 5 个要点，并给出适合分享的标题...
```

### 8.4 推荐接口

```python
def build_search_snippet(content: str, query: str, max_length: int = 100) -> str:
    pass
```

### 8.5 验收标准

1. 正文命中时显示上下文摘要。
2. 摘要不过长。
3. 摘要中关键词高亮。
4. 无正文命中时显示默认摘要。

## 9. 任务七：快捷键可视化提示

### 9.1 目标

用户不用读文档，也能知道核心快捷键怎么用。

### 9.2 要做什么

在主界面和快速窗口中展示常用快捷键提示。

### 9.3 主界面建议展示

位置：底部状态栏、帮助区域、设置页或欢迎卡片。

内容：

```text
Ctrl + Alt + P  呼出搜索
Ctrl + N        新建 Prompt
Ctrl + F        搜索
Enter           复制选中 Prompt
Esc             关闭窗口
```

### 9.4 快速窗口建议展示

位置：搜索结果底部。

内容：

```text
↑↓ 选择    Enter 复制并关闭    Shift+Enter 复制不关闭    Esc 关闭
```

### 9.5 要求

1. 快捷键提示不能占太多空间。
2. 快捷键如果来自配置，应显示配置后的值。
3. 如果当前功能未实现，不要显示对应快捷键。
4. 文案要短。

建议建立快捷键注册表，后续统一管理快捷键显示和快捷键配置。

```python
class ShortcutRegistry:

```

本阶段可以先用静态配置实现，但代码结构要方便后续替换成动态配置。

### 9.7 验收标准

1. 主界面能看到核心快捷键提示。
2. 快速窗口能看到 Enter、Shift+Enter、Esc 提示。
3. 提示与实际行为一致。
4. 未实现的快捷键不显示。

```python
def record_prompt_used(prompt_id: str) -> None:
```

Ctrl + Enter 后续可做自动粘贴。

本阶段如没有稳定实现，不要强做。

## 11. 数据兼容要求

### 11.1 不允许破坏现有数据

本阶段不得要求用户手动迁移现有 Prompt 文件。

如果需要新增字段，必须满足：

1. 老文件可正常读取。
2. 新字段有默认值。
3. 保存时不丢失旧字段。
4. 读取失败时有错误提示。

### 11.2 推荐新增元数据

如项目目前支持 front matter，可考虑新增：

```yaml
title: 示例 Prompt
category: 写作
tags: [总结, 润色]
favorite: false
use_count: 0
last_used_at:
created_at: 2026-05-04T00:00:00
updated_at: 2026-05-04T00:00:00
```

如果当前项目没有稳定 front matter，不要为了本阶段强行迁移数据格式。

---

## 12. UI 边界要求

### 12.1 不大改现有页面

本阶段只允许小范围增加：

1. Toast 层
2. EmptyState 组件
3. 搜索结果高亮显示
4. 搜索结果摘要区域
5. 快捷键提示区域
6. 从剪贴板新建按钮

### 12.2 不改变核心布局

不得把当前主界面重构成全新布局。

不得引入复杂侧边栏、工作台、画布、在线市场等新页面。

### 12.3 保持键盘优先

快速窗口相关功能必须优先保证键盘可用。

鼠标操作可以有，但不是重点。

---

## 13. 错误处理要求

所有新增功能必须有兜底。

### 13.1 剪贴板错误

必须处理：

1. 剪贴板为空。
2. 剪贴板不是文本。
3. 剪贴板访问失败。
4. 剪贴板文本过长。

### 13.2 搜索错误

必须处理：

1. 搜索词为空。
2. 搜索词含特殊字符。
3. 高亮失败。
4. 摘要生成失败。

### 13.3 复制错误

必须处理：

1. 复制失败。
2. 无选中项。
3. Prompt 内容为空。

### 13.4 UI 错误

任何新增组件出错时，不应导致主程序崩溃。

## 14. 测试要求

### 14.1 必测场景

1. 无 Prompt 的首次启动。
2. 有 Prompt 的正常启动。
3. 搜索有结果。
4. 搜索无结果。
5. 搜索中文。
6. 搜索英文。
7. 搜索特殊字符。
8. 点击复制。
9. 快速窗口 Enter 复制。
10. 快速窗口 Shift + Enter 复制。
11. 快速窗口 Esc 关闭。
12. 剪贴板有文本时新建 Prompt。
13. 剪贴板为空时新建 Prompt。
14. 保存 Prompt 成功。
15. 保存 Prompt 失败。

### 14.2 推荐单元测试

建议为以下纯函数补测试：

1. `highlight_text(text, query)`
2. `build_search_snippet(content, query, max_length)`
3. `build_prompt_draft_from_clipboard_text(text)`
4. `normalize_search_query(query)`
5. `extract_title_from_text(text)`

### 14.3 手动验收流程

#### 流程一：快速复制

```text
打开应用
按 Ctrl + Alt + P
输入关键词
选择结果
按 Enter
确认 Toast 出现
确认窗口隐藏
确认剪贴板内容正确
```

#### 流程二：复制但不隐藏

```text
打开快速窗口
输入关键词
按 Shift + Enter
确认 Toast 出现
确认窗口仍显示
确认剪贴板内容正确
```

#### 流程三：从剪贴板新建

```text
复制一段 Prompt
点击从剪贴板新建
确认表单正文已填充
确认标题已自动生成
选择分类
保存
确认列表出现新 Prompt
确认 Toast 出现
```

#### 流程四：搜索高亮

```text
搜索“翻译”
确认标题/标签/摘要中的“翻译”高亮
清空搜索
确认高亮消失
```

## 17. 建议开发顺序

### 第 1 步：基础服务

1. 完成手动验收。
2. 补充关键纯函数测试。

4. 更新快捷键说明。
